# 通用开发规则

## Denzic 构建缓存与密钥（Owner 2026-11-12）

本地原生构建优先使用各项目固定的 E 盘可重建缓存，同一工具链复用目标目录；批次目录只保留日志、结果和交付物，不为每次检查另复制完整 Cargo 编译树。Windows 开发／测试配置默认关闭大体积调试符号和增量副本，正式发布优化按项目原配置。清理只针对明确的可重建产物，当前作业、源码、真实录音、验收证据和已验证交付物保持可用。

2026-11-12复发修复补充：共用实现为 `scripts/development_storage.py`。Companion 的当前固件入口固定复用 `firmware/shared-wba-build`，继续由原编译器的源码、头文件、参数及对象哈希决定是否复用，各版本只导出成品和诊断；本地Windows入口固定复用 `shared-windows-target`。两个入口均持有操作系统排他锁，忙时不另建副本。新构建开始前检查 `.build-cache` 80GiB预算，并为本次作业预留空间，磁盘至少保留30GiB；超额明确停止新构建，定位生成原因，不自动删除资料、不自动放大预算。此为入口容量检查，不冒充对所有手写脚本或在途进程的系统级磁盘配额。默认不建定时清理任务；未来新开发入口沿本实现接入，例外在原待办记明原因和空间估算。

签名私钥属于持久凭据，放在用户目录的 `.denzic/keys/<项目>/` 等独立位置，不放 `.cache`、`.build-cache` 或临时目录；仓库只保存公钥、指纹和位置配置。Git 自动打包失败先记录并修原因，关闭受影响仓库的自动重试，核对无打包作业后清掉未完成的 `tmp_pack_*`，不删除正式对象或改写历史来腾空间。

Owner同步：2026-10-17。Grok、Claude、Codex、Cursor共用。通用规则只有以下三条；项目专属要求由对应项目的AGENTS.md承载。

1. **防回退**：关键功能保留已验证版本、提交和失败证据；复发先对照历史定位改坏的位置，修源头，按受影响范围验证，不重复跑无关检查。
2. **开发时间线**：每个项目沿用一份完整日志，按实际时间记录改了什么、对应版本/提交、结果和未解决问题；保留失败与回退，不把测试和文档数量当功能进展。
3. **待办续作**：用户插话提出的新事项默认记入该项目现有待办，保留原任务；明确说“插队、优先、先做”的先记录当前工作点，再优先处理。补充现象并入对应事项，问进度或澄清不重复建任务。每完成一项先更新结果、读取待办，再继续最高优先级的可执行项，不等用户反复说“继续”；遇到依赖则保留未完成状态并推进其它可执行项。只有用户明确取消或替换才移除原事项。优先选择当前最影响实际使用的完整问题，围绕根因连续完成实现、受影响联动及必要验证，形成可用结果后再切换；小改动、单项测试、日志或中间候选不单独视为完成，也不因阶段性汇报停下等待“继续”。客观依赖导致无法闭环时明确保留未完成证据，继续同一目标内可独立推进的实质工作；不为追求完整而重复无变化的试验、增加无收益保护或掩盖未测条件。
